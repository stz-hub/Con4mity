Architecture

Con4mity est un SIEM léger : un backend FastAPI sert l’API sous le préfixe /api et les fichiers statiques du dossier frontend/ à la racine du site. Les données viennent de PostgreSQL (utilisateurs, alertes, journal d’activité) et OpenSearch (logs index con4mity-logs-*).

Pages de l’interface

  • Vue d’ensemble (overview.html) — indicateurs, graphiques (Chart.js CDN), frise temporelle.
  • Logs (logs.html) — flux avec recherche et filtres (dates, hôte, type d’événement, utilisateur). Les colonnes hôte / sévérité / message s’appuient sur les champs dérivés con4mity_ui_* renvoyés par l’API (normalisation syslog / ECS côté backend/log_normalization.py).
  • Alertes — vue regroupée ou détail, tiroir d’investigation, lien vers les logs filtrés.
  • Rapports — export CSV navigateur.
  • Automatisation — playbooks démo et historique (operator_activity).
  • Paramètres — langue FR/EN/ES et fiches des domaines à brancher (MFA, rétention, etc.).

API utile

  • POST /api/login — JWT.
  • GET /api/overview — synthèse (stats + agrégations légères sur échantillon de logs, top_hosts et top_source_ips).
  • GET /api/logs — paramètres q, host, event_type, user_name, from_ts, to_ts, size ; réponse enrichie (con4mity_ui_host, con4mity_ui_severity, con4mity_ui_message, con4mity_ui_timestamp).
  • GET /api/alerts, PATCH /api/alerts/{id}.
  • GET /api/playbooks, POST /api/playbooks/{slug}.
  • GET /api/activity — nécessite la migration SQL 003_operator_activity.sql.

Migrations SQL

Exécuter les scripts dans backend/sql/ sur la base PostgreSQL (alertes, colonnes, table operator_activity, etc.).

Raspberry Pi 5

Prévoir Python 3 avec venv, limiter la taille des requêtes OpenSearch, et héberger Chart.js en local si le Pi n’a pas Internet pour le CDN.

Architecture

Con4mity is a lightweight SIEM: a FastAPI backend exposes /api and serves static files from frontend/. Data comes from PostgreSQL (users, alerts, activity log) and OpenSearch (con4mity-logs-*).

UI pages

  • Overview — KPIs, Chart.js charts, timeline.
  • Logs — stream with search and filters; host / severity / message use derived con4mity_ui_* fields from the API (backend/log_normalization.py).
  • Alerts — grouped or flat view, drawer, link to filtered logs.
  • Reports — browser CSV export.
  • Automation — demo playbooks and history.
  • Settings — FR/EN/ES language and roadmap cards.

Useful API

  • POST /api/login — JWT.
  • GET /api/overview — summary (top_hosts and top_source_ips).
  • GET /api/logs — query params q, host, event_type, user_name, from_ts, to_ts, size; enriched hits (con4mity_ui_host, con4mity_ui_severity, con4mity_ui_message, con4mity_ui_timestamp).
  • GET /api/alerts, PATCH /api/alerts/{id}.
  • GET /api/playbooks, POST /api/playbooks/{slug}.
  • GET /api/activity — requires 003_operator_activity.sql.
